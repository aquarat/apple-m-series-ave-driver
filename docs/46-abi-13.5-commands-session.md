# Commands and session setup on macOS 13.5 vs 26.6.2

Docs [07](07-commands-abi.md), [13](13-userclient.md), [20](20-command-structs.md),
[21](21-buffer-publication.md), [37](37-start-avc-session.md),
[38](38-dimension-convention.md) and [39](39-input-format.md) were read from
**macOS 26.6.2** (25G83). The coprocessor firmware this machine runs is
**macOS 13.5** (22G74), proven byte-for-byte in [43](43-macos-13.5-firmware.md).
This document re-reads every concrete claim of those docs against the 13.5
firmware image and 13.5 `AppleAVE2` kext, and records **both** values.

Neither column supersedes the other. 26.6.2 stays authoritative for 26.6.2
firmware, which Asahi may move to later; 13.5 is what runs today. A driver
should carry both ABIs and pick one by detected firmware version (§8).

Verdicts: **same on both** (positive 13.5 evidence of the same value and
meaning), **DIFFERS by version**, **cannot verify on 13.5** (what was tried is
stated). Confidence per row: **confirmed** (read from an instruction, VA
given), **inferred** (chain stated), **unknown**.

Addresses: 13.5 firmware VAs are image VAs (`__TEXT` VA 0 = file `0x4000`,
`__DATA` VA `0xec000` = file `0xf0000`). 13.5 kext VAs are kernelcache VAs.
Reproduce with `AVE_MACOS=13.5 python3 tools/disas.py --fw|--kext --addr VA -n LEN`.


## 0. Summary

| Question | 26.6.2 | 13.5 | Verdict |
|---|---|---|---|
| Command ids | 1..12, id 5 hole, AVC/HEVC and engine chosen by header fields | 1..14, one id per operation, codec in the id; id 10 unhandled | **DIFFERS by version** — confirmed |
| Header | 0x40, u64 CID `+0x10`, enc type `+0x1C`, slot `+0x20`, prio `+0x24`, timeout `+0x30` | 0x40, **u32** CID `+0x10`, codec `+0x18`, slot `+0x1C`, prio `+0x20`, timeout `+0x28` | **DIFFERS** — confirmed |
| Codec encoding on the wire | 1 = AVC, 2 = HEVC (`+0x1C`) | 0 = AVC, 1 = HEVC (`+0x18`) | **DIFFERS** — confirmed |
| Config size / Open size / Start_AVC size / Process_AVC size | `0x78` / `0x48` / `0x3180` / `0x63D8` | `0x70` / `0x40` / `0x10E10` / `0x1940` | **DIFFERS** — confirmed both sides |
| Wrong size | assert + spin | assert + spin (`_bsp_assert_fail`, `b .`) | same on both — confirmed |
| Host↔firmware interface-version check in AVE | none found | **none found**; the "Host and FW Interface is mismatched" string is in the **GPU (AGX) firmware**, not AVE (§7) | — |
| User client | selectors 1..10 | selectors 0..8, different sizes | **DIFFERS** — confirmed |

The practical consequence: **no 26.6.2 command reaches a 13.5 handler intact.**
Config (id 1 on both) is the first thing a driver sends, and a 26.6.2-shaped
Config (`0x78`) fails 13.5's `insize == 0x70` assert at `0xd704`: `b.ne 0xde48` →
`_bsp_assert_fail` and the coprocessor spins in `b .` at `0xde8c`. **Confirmed** (instructions); the effect on
hardware is **inferred** and must not be tried (AGENTS.md).

That the 26.6.2 kext carries twice the symbols (10844 vs 5248) and 21 vs 13
`AVE_IOP_Config_*` variants is plausibly support for SoCs and codec features
released after 13.5 ([43](43-macos-13.5-firmware.md) §5). **Inferred**; nothing
here depends on it.

## 1. Command ids and sizes

### 1.1 Firmware side (13.5)

`CFlowControllerBase::CmdProcessor(void*, u32, u32*)` at `0xd614`:

```
d65c:  ldrh w8, [x23]            ; id, u16 at +0
d69c:  strh wzr, [x23, #2]       ; +0x02 zeroed on receipt (as on 26.6.2)
d6b4:  ldr  w26, [x23, #24]      ; logged as "#### AVE CODEC [%d] CMD = %#04x [%s]" (0xbcaa8)
d6e0:  sub  w8, w8, #0x1
d6e4:  cmp  w8, #0xd             ; ids 1..14
d6e8:  b.hi 0xe218               ; default: no handler, *out = 0, return 0
d6ec:  adr  x9, 0xe2e8           ; 14 int32 offsets relative to 0xd6f4
```

Each target compares `insize` (`w22`) against a constant, logs, calls
`CController::Post(cmd, insize)` (`0xa1f14`, must return 0, else assert
`"rcLocal == 0"`), then the handler. Enum names are the firmware's own table
`GetString_eCAveCmdID` (`0x3ca54`) → 16-byte `{id, char*}` records at
`0xed060`.

the id the builder writes. **Confirmed**, both sides. The host-side codec

firmware reads 16 bits. **Same on both**, confirmed.

three-argument `memset` on 13.5, where 26.6.2 used a two-argument routine.
**Inferred** from the argument pattern.

arrays 41 entries apart. No bound check exists in 13.5 `SendFwCmd` itself (its
only compares are the state gate `== 3` and two DPM flags,
`0xfffffe0008efb784`–`c0`). **DIFFERS**, confirmed.

Commands still go out on IPC channel 1: `AVE_IPC::Send(ch = 1, buf, len)`
(`mov w1,#0x1` `0xfffffe0008efb2d0`, `bl 0xfffffe0008f25538`). **Same on both**.

with the IPC object at `this->[192]` (26.6.2 `[192]`/`[224]`; host-internal).

Max concurrent clients: `RegisterClient` `cmp w8,#0x80` at `0x17790`. **Same
on both** (128).

### 2.1 Replies (firmware → host)

`CFlowControllerBase::NotificationToHost(u16 id, u32 cid, AVE_FW_ERROR,
void* hdr_tail)` (`0x13684`), called with `hdr_tail = cmd + 0x1C`. It builds a
**0x40** message for `CONFIG/START/RESET/INIT/UNINIT/FLUSH/STOP/COMPLETE_DONE`
(bitmask `0x71F` over `id - 0xE01`, `0x136d0`) and **0x48** for
`ENCODE_DONE/LRME_DONE` (`tst w8,#0x60` `0x13784`): `+0x00` u16 id, `+0x10`
cid, `+0x1C` the command's slot, `+0x38` status, and for the 0x48 form `+0x40`
= the command's `+0x20`. Success status is **`0xEE0000`** (`ProcessConfig`
`0xe730`); `START` failure `0xEE0001` (`0xe950`–`e958`), `AVC_INIT` failure
`0xEE0002` (`0xef00`–`ef0c`). **Confirmed.** (26.6.2 used 0, -1004, -1008 —
[20](20-command-structs.md) §1/§3.4.) **DIFFERS.** How the host consumes these
is the IPC agents' scope ([36](36-ipc-implementation.md)); not re-read here.

## 7. The "Host and FW Interface is mismatched" string

**It is not AVE's.** The string is at dump offset `0x13e7a3` of
`data/blobs/iboot-window-16m.bin` (physical `0x10000c667a3`). The 13.5 AVE
`__TEXT` occupies dump offsets `0`–`0xec000` and its `__DATA` begins at
`0xf68000` ([43](43-macos-13.5-firmware.md) §3–4), so `0x13e7a3` is outside
both. Its neighbours are AGX GPU firmware strings: `"G13 Firmware
initializing"` (`0x13e48a`), `"AGX_CR_USC_VDM_SERV: 0x%llx"` (`0x13e509`),
`"agfG13XEnableAFRCPG"` (`0x13e662`), `"Unable to grab init data from host"`
(`0x13e780`, immediately before), `"Host-mapped FW allocations are disabled"`
(`0x13e7f0`, immediately after); [31](31-bringup-state.md) §2 already places GPU
firmware in that region (tag list at `0x10000c652a0`). **Confirmed** (dump
contents); that it is the GPU firmware's init-data version check is
**inferred** from the neighbours.

Controls: `grep -a` for the string finds it once in the dump and **zero** times
in the 13.5 AVE image, the 26.6.2 AVE image, the 13.5 `AppleAVE2` kext and the
26.6.2 kext; the same grep finds `"FW version : %s"` in the 13.5 AVE image
(string VA `0xcd44d`) and in the dump at offset `0xcd44f` (the same VA plus
its two leading spaces, as expected with `__TEXT` at dump offset 0), so the
method finds AVE strings where they exist.

**Is there any AVE host↔firmware interface-version check on 13.5? None found.**
What was looked at:

- 13.5 AVE firmware strings containing `version`, `interface`, `compat`,
  `magic`, `protocol` (case-insensitive): only `"  FW version : %s"`, RTKit
  symbol names, and unrelated `wrDmaBin…` hits. `"  FW version : %s"` is used
  by `CEnvironment::LocalInfo` (`adr` at `0x9f460`, `0x9fe58`) to *log*
  `GetRTKClientVersion()` (`0xa5968` → `"AppleAVE2FW-6070.11.1"`, `0xee9ee`) —
  a print, not a comparison.
- 13.5 kext strings with `version`/`mismatch`/`compat`: only
  `IOExternalMethodArguments version`, frame-number / command-type / frame-type /
  IPC-channel-buffer mismatch logs.
- The 13.5 `Config` handler (§3), `START` handler (§4) and dispatcher (§1.1):
  no field is compared against a constant other than `insize`.

So on both versions the **only** interface check the AVE firmware performs is
the per-command `insize` assert, and it fails closed (spin), not with an error
reply. **Confirmed** for the functions listed; absence elsewhere is not proven.
